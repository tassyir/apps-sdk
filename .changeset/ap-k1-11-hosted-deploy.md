`tassyir deploy` deploys an app on Tassyir Hosting (`hosting.mode = "tassyir"`). It builds the bundle with esbuild (0.28.2, now a dependency): one ES module from `--entry` or the first of `src/worker.ts`, `src/worker.js`, `src/index.ts`, `src/index.js`, ES2022, `.html` and `.css` imported as text. It checks it before anything is sent, by the API's own upload rules (the `BUNDLE_*` codes: text files of the allowed types, 100 files and 3 MB, safe paths, a `main` ES module, a lockfile of 1 MB) and the scan's code checks (no `node:` import, no `import()` of a run-time name, no code from strings, no request to a Tassyir domain or to a host outside `hosting.allowed_hosts`, a `fetch` handler exported), refusing with `BUNDLE_INVALID` (exit 4) and each problem's place in your source. It then uploads `{ manifest, bundle }` with the project's lockfile, and follows the version's scan until it is released (exit 0), held for a person (`in_review`, exit 0), failed with its findings (`VERSION_SCAN_FAILED`), or ended without a verdict (`SCAN_TIMED_OUT`, `SCAN_INCOMPLETE`, `SCAN_DISPATCH_FAILED`, `SCAN_RESULT_INVALID`, exit 5: upload the same bundle again). `--timeout <seconds>` (default 1800, `0` answers at once); Ctrl-C stops waiting and never the scan. With `--json` it prints the uploaded version first (`"step": "uploaded"`), then the verdict, with the version as the API reports it. `APP_VERSION_UNCHANGED` answers with that version's state; `APP_VERSION_CONFLICT`, `APP_HOSTING_NOT_AVAILABLE`, `APP_HOSTING_NOT_CONFIGURED` and `PAYLOAD_TOO_LARGE` come with a fix that names what to run. New command `tassyir app version [n]` shows one version (a hosted one with every check, finding and the AI review), `--follow` waits for its verdict. Exit code 4 now also means a bundle that does not build or pass, 5 a scan still running. The developer API types follow its OpenAPI document at backend `e6f930db` (`bundle` on an upload, `hosting` on every version, the hosting codes; the rate limit's bare-string refusal is the `RateLimitError` schema, formerly `ThrottlerError`, in `DeveloperApiErrorBody`). The library entry exports `validateHostedBundle`, `checkBundleCode` and `buildHostedBundle`; `CliIo` gains an optional `onInterrupt`, and `sleep` an optional `AbortSignal`.
